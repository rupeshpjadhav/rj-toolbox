My Toolbox tool guides

My Toolbox is a free set of browser-based utilities for developers, testers and anyone who works with data. Below is what each tool does, when it helps and a practical tip. Choose a tool from the menu on the main page.

  • YAML Validator

Test Data Generator

Builds realistic fake records for testing: you define columns (row number, UUID, full/first/last name, email, phone number, city, country, random numbers, random words), pick how many rows you want, and export as JSON, CSV, XML, HTML, SQL inserts, Python or JavaScript.

Good for:

  • Seeding a local or staging database with believable users
  • Load and performance tests that need thousands of unique rows
  • Demo screens and screenshots without exposing real customer data
  • Unit-test fixtures in the exact language format you need

Tip: Use synthetic data instead of copying production records. It keeps personal data out of test environments, which most privacy rules (including India's DPDP Act and the GDPR) expect.

Random Generator (passwords and keys)

Creates strong passwords with a chosen length and character sets (uppercase, lowercase, numbers, symbols, with an option to drop look-alike characters such as 1, l, I and 0), plus random keys for development use.

Good for:

  • A fresh password for a new account
  • API secrets and tokens for local development
  • Random identifiers for test environments

Tip: Length beats complexity: a 16+ character password with mixed sets is far harder to guess than a short one full of symbols. Store passwords in a password manager, not in a text file.

Open Random Generator

Universal Data Converter

Converts between Column (one value per line), CSV, TSV, JSON and XML, in any direction. It can auto-detect the input format, accepts a file upload, and lets you choose the quote style of CSV and TSV output.

Good for:

  • Turning a spreadsheet export (CSV) into JSON for an API or mock server
  • Pasting a column of values from Excel and getting a JSON array
  • Converting JSON API responses back into CSV for analysis
  • Converting an XML export into JSON, or a JSON payload into XML

Tip: When a CSV has commas inside values, make sure those values are quoted; otherwise the columns shift. In XML, repeated elements such as <item> become rows. Check the first few converted rows before using the output.

Open Universal Data Converter

JSON Toolkit

Formats, validates and beautifies JSON. It also accepts JavaScript object notation (unquoted keys), can stringify the result, and lets you choose 2, 4 or 8 spaces of indentation.

Good for:

  • Making a minified API response readable
  • Finding the exact spot where invalid JSON breaks
  • Converting a JavaScript object literal into strict JSON

Tip: The most common JSON errors are trailing commas, single quotes instead of double quotes, and unquoted keys. The validator points to the line so you can fix it quickly.

Open JSON Toolkit

JavaScript Toolkit

Compresses (minifies) JavaScript, with optional variable-name mangling and compression passes, and validates code for syntax errors and likely problems.

Good for:

  • Shrinking a small script before embedding it in a page
  • Checking a snippet for syntax errors before deploying
  • Quick experiments without setting up a build tool

Tip: Keep the original readable file in version control and treat the minified output as a build artifact. Mangling names can break code that relies on function or variable names at runtime.

Open JavaScript Toolkit

SQL Formatter and Validator

Beautifies or minifies SQL queries and highlights syntax errors. It supports Standard SQL, MySQL, PostgreSQL and Transact-SQL (T-SQL), and can set keyword case (for example UPPERCASE).

Good for:

  • Reading a long one-line query copied from logs
  • Standardizing query style before a code review
  • Spotting a missing comma or bracket

Tip: Pick the dialect that matches your database; functions and quoting rules differ between MySQL, PostgreSQL and SQL Server.

Open SQL Formatter and Validator

Difference Checker

Compares two blocks of text, or two uploaded files, and shows the changes line by line: added lines in green and removed lines in red.

Good for:

  • Comparing two versions of a config file
  • Checking what changed between two API responses
  • Reviewing edits to a document or script

Tip: Format both inputs the same way first (for example, beautify both JSON files) so the diff shows real changes instead of whitespace noise.

Open Difference Checker

Case Converter

Changes text to lowercase, UPPERCASE or Title Case, with the result in a separate output box.

Good for:

  • Fixing text typed with Caps Lock on
  • Making headings consistent
  • Normalizing lists of names or tags

Tip: Title Case capitalizes every word; style guides differ on short words like 'of' and 'and', so review headlines before publishing.

Open Case Converter

Text Styler

Converts text into programming naming styles: camelCase, PascalCase, snake_case, kebab-case and Capitalized Case.

Good for:

  • Naming variables, functions and classes consistently
  • Creating URL slugs and file names (kebab-case)
  • Converting database column names (snake_case) to JavaScript properties (camelCase)

Tip: Follow the convention of the language you are writing: camelCase for JavaScript variables, PascalCase for classes and React components, snake_case for Python and most SQL columns.

Open Text Styler

YAML Validator

Checks YAML files for syntax errors, which is useful for configuration files such as Kubernetes manifests, Docker Compose files and CI pipelines.

Good for:

  • Catching an indentation error before a deployment fails
  • Checking a CI/CD pipeline file
  • Validating Docker Compose or Kubernetes manifests

Tip: YAML does not allow tab characters for indentation, and a single misaligned space changes the structure. Validate before committing config changes.

Open YAML Validator
